Forecast: Frizzy
(Weather, but for Hair)

Veronica Andrade·Oct 4, 2026

Since my master's research on technoanimism, I've kept experimenting with mediating data and noisy inputs into something else. Weather apps tell me it's 24°C and 48% humidity. Cool, but what does that mean for my hair? This small experiment takes a weather feed and renders it as a short sentence, inspired by the old Poncho weather app (and my very own experience of getting puffy hair in humid environments).

The itch

I wanted to see if the idea was actually fun and useful before committing to a native widget. So I scoped the first version down to the cheapest thing I could build to test it: a webpage with a widget-style card, built with Claude. Everything runs client-side in plain HTML, CSS and JS, with no build step. Weather comes from Open-Meteo, which is free and needs no API key.

Since it isn't a native widget, I wanted the browser version to act and feel like one. The card is draggable like a macOS widget, using pointer events so mouse and touch share one code path. It's clamped to the viewport, and its position persists between visits:

The rules

The core is a small rules engine. Weather data becomes a "state", and each state owns a bank of lines. The two never mix, so I can retune thresholds without touching the jokes/puns, or the reverse. Thresholds live in one config object:

const T = {
  gustWeight: 0.75, 
  rainLight: 0.5, rainMod: 2, rainHeavy: 7.5, // mm/h
  windBreeze: 20, windStrong: 30, windSevere: 45, // km/h
  humidRH: 70, veryHumidRH: 80, soupRH: 90, // % RH
  good:   { t: [15, 25], rh: [35, 65], wind: 20 }, 
  utopia: { t: [18, 25], rh: [40, 55], wind: 15 } 
};

Rules are an ordered list where the first match wins, so the order is the priority:

const RULES = [
  { id: 'storm', cond: 'wind', test: w => w.rain >= T.rainMod && w.eff >= T.windStrong },
  { id: 'gale',  cond: 'wind', test: w => w.eff >= T.windSevere },
  // ...
  { id: 'ok', test: () => true } // fallback
];
const rule = RULES.find(r => r.test(weather));

I first wrote the thresholds and priority order myself before generating any code, and tested the rules with ChatGPT's help. Some interesting cases showed up:

1. Humidity somewhat depends on temperature. The same relative humidity can have different implications for hair depending on the temperature. 85% humidity at 10°C suggests cold, damp air, while 85% at 30°C adds heat and sweat. The system combines humidity with temperature when deciding which hair-weather condition to trigger.

2. Gusts escalate wind. A moderate sustained wind can feel much more disruptive when gusts are significantly stronger. E.g., 15 km/h sustained wind with 35 km/h gusts isn't really the same as a steady 15 km/h breeze: the gusts can suddenly move and tangle hair, so the system uses them to escalate the wind category when they cross higher thresholds:

W.eff = Math.max(W.wind, W.gust * T.gustWeight);

A super simple debug/tuning panel lets me preview different lines, locations and weather conditions using a couple of force-state options. Gradients shift with the weather, with each condition family getting its own palette.

The copy

I asked Claude which LLM I should use to generate the jokes live, and the answer was that I didn't really need one: a small rules engine with a hand-edited line bank is free, predictable, and fast, and it means every line the widget can say has been read by a human (me). The AI's best job was helping me write the line bank, rather than coming up with a new line for every weather update. Lines are stored per state, with placeholders for real values:

const LINES = {
  gale: [
    "Wind's out here modeling harder than you. Secure the strands.",
    "{wind} km/h gusts. Loose hair is a hostage situation."
  ],
  // ...
};

Where I stopped

I considered a native macOS widget and decided against it. The browser version already answered the part I was curious about, and I was able to share it with friends and get their feedback on it.

One thing I took away from building it was that having the rules figured out before jumping into pair coding with Claude made the whole process much smoother, and also reinforced something I keep coming back to with prototypes (and, as a designer, always worth keeping in mind): you often don't need to build much to find out what you want to know. In this case, a few rules and a distinctive tone of voice were enough to validate the idea before spending more time adding features or turning it into a proper macOS widget.

If I picked it up again, I'd probably play around with basic hair-type settings. The same 85% humidity means something very different for straight, wavy or curly hair, which could make the recommendations a little more personal and (probably) more accurate.

In the meantime, you can check out the prototype here. Hope the forecast is kind to your hair.
